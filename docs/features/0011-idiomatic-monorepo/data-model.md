# Data model: Idiomatic monorepo

FEAT-0011 changes repository metadata and retained records. It does not add a product runtime entity or database table.

## Owner

An Owner is the canonical location for one built, deployed, shared, automated, or documented responsibility.

| Field                | Meaning                                        | Rules                            |
| -------------------- | ---------------------------------------------- | -------------------------------- |
| Path                 | Canonical repository directory                 | Exactly one active path          |
| Kind                 | Application, package, script, or documentation | Determines placement             |
| Subject              | The product, module, or rule owned by the path | Must be concrete                 |
| Supported edge       | The allowed consumer boundary                  | Private edges remain explicit    |
| Runtime dependencies | Packages needed by production source           | Must remain acyclic              |
| Test dependencies    | Private packages used only by tests            | Must not enter production source |

### Validation

- Application owners live under `apps/*` and contain an executable process.
- Package owners live under `packages/*` and contain a manifest with real tasks or imports.
- Root scripts are thin and name one repository-wide action or rule.
- No active owner uses a removed root path.

## Proof level

A Proof level classifies a test by the boundary it exercises. It is nested under an Owner.

| Level       | Subject boundary                                                  | External dependency                    |
| ----------- | ----------------------------------------------------------------- | -------------------------------------- |
| Unit        | Owner source                                                      | None beyond process-local dependencies |
| Conformance | Shared observable Budget commands through an adapter              | Owner-local implementation             |
| Package     | One exact packed archive installed outside the workspace          | Temporary package consumer             |
| System      | Installed PostgreSQL product or Cloud process and real PostgreSQL | Disposable PostgreSQL 18.6             |
| Performance | One exact SDK archive under a reference method                    | Declared reference host                |

### Validation

- A test has one subject owner even if its result contributes to more than one review claim.
- SDK measurement remains nested under SDK package tests but writes a distinct record schema.
- Shared conformance scenarios import no implementation.
- Deployment-specific controls stay owner-local.

## Workspace edge

A Workspace edge is a declared dependency between two pnpm workspaces.

| Field            | Meaning                                        |
| ---------------- | ---------------------------------------------- |
| Consumer         | Workspace that declares the dependency         |
| Provider         | Workspace named by the dependency              |
| Scope            | Runtime, build-time, or test-time              |
| Allowed paths    | Source areas that may import the provider      |
| Prohibited paths | Source areas that must not import the provider |

### Validation

- Production SDK, PostgreSQL, and Cloud source has no Keynes workspace dependency.
- Root generation scripts may consume the contract generator.
- Product tests may consume conformance or testkit through declared test-time edges.
- Contracts never depend on product implementations or testkit.
- Testkit never contains Budget semantics.

## Generated target

A Generated target binds the neutral contract model to one owner-local renderer and output.

| Field        | Meaning                                   |
| ------------ | ----------------------------------------- |
| Target ID    | Stable logical name                       |
| Destination  | Owner-local checked-in path               |
| Renderer     | Owner-local rendering function            |
| Orchestrator | Root call order and combined drift result |
| Digest       | Hash or checksum used for drift checks    |

### State transitions

```text
canonical inputs -> neutral model -> PostgreSQL renderer -> installation identity
                                   |                           |
                                   |                           `-> Cloud renderer
                                   `-> SDK renderer

owner renderer -> generated bytes -> compare with owner-local target
                                     |
                                     +-- equal: no change
                                     `-- different: write on generate, fail on generate:check
```

Generation must be deterministic. Running it twice produces no second change.

## Local output

A Local output is a generated archive, result, report, or measurement under `.artifacts/`.

| Field             | Meaning                                                                              | Rules                             |
| ----------------- | ------------------------------------------------------------------------------------ | --------------------------------- |
| Lane              | SDK package, SDK performance, PostgreSQL package, PostgreSQL system, or Cloud system | Lanes remain distinct             |
| Subject           | Exact package or deployment tested                                                   | Must be explicit                  |
| Revision          | Source commit and clean-state facts                                                  | Must bind the run                 |
| Artifact identity | Archive or installation digest when applicable                                       | Must match the tested input       |
| Outcome           | Passed or failed                                                                     | Must not hide partial failure     |
| Exclusions        | Unsupported or unexecuted claims                                                     | Use `NOT RUN`                     |
| Path              | Ignored non-overwriting file                                                         | Parent directories may be created |

### State transitions

```text
absent -> writer reserves path -> run -> cleanup -> final record
   |              |                |        |
   |              |                |        `-- cleanup failure: no passing record
   |              |                `-- run failure: failed output only when schema permits
   |              `-- existing path: refuse overwrite
   `-- create parent directories as needed
```

## Retained evidence

Retained evidence is an accepted historical JSON record stored beside its owning feature.

| Field             | Meaning                                        | Rules                               |
| ----------------- | ---------------------------------------------- | ----------------------------------- |
| Owning feature    | Feature whose completed claim cites the record | One owner                           |
| Recorded revision | Original source revision                       | Never changed by relocation         |
| Old path          | Former tracked `artifacts/` path               | Preserved in the migration manifest |
| New path          | Feature-local evidence path                    | Required for moved records          |
| SHA-256           | Hash before and after move                     | Must be identical                   |
| Proof boundary    | What the record proves and excludes            | Must remain unchanged               |

Moving retained evidence has no acceptance-state transition. The record stays historical evidence for the same revision.

## Evidence disposition

An Evidence disposition accounts for one former tracked artifact.

| Disposition             | Meaning                                                                            |
| ----------------------- | ---------------------------------------------------------------------------------- |
| Moved byte-identically  | Selected accepted JSON retained beside its owner                                   |
| Superseded              | A later accepted record owns the current historical claim                          |
| Dirty attempt           | The record cannot bind a passing claim to one source revision                      |
| Failed attempt          | The record is useful only in CI or prose that describes the failure                |
| Duplicate or incomplete | Another record contains the accepted result, or this file is not a complete result |
| Binary removed          | A generated archive is identified by digest and can be rebuilt                     |

Every former tracked artifact has exactly one disposition.
